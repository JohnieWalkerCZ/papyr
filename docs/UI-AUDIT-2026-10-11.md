# Papyr UI audit — 2026-10-11

## Scope and method

Compared the implemented home/local-note screen, Typst proof, and development whiteboard with `UI_UX.md` and `DESIGN_RULES.md`. Captured screenshots at 1440, 1024, 768, 390, and 360 CSS pixels in light and dark system themes. Czech labels were checked on the implemented Papyr chrome. Measured horizontal overflow and Papyr control hit heights in Chromium; ran axe WCAG 2.0/2.1/2.2 A/AA scans and keyboard focus checks.

The production whiteboard route is intentionally license-blocked, so its screenshots and checks use the development proof editor. Screenshot sets are in `artifacts/ui-audit/before/` and `artifacts/ui-audit/after/` (30 before, 34 after).

## Findings and fixes

### P1 — No dark palette

**Before:** `prefers-color-scheme: dark` still rendered the light palette on every route.  
**Fix:** Added semantic dark tokens, correct browser theme color, and tldraw's system color-scheme mode.  
**Result:** Body, controls, editor canvas, selection, and browser chrome follow the system preference.

### P1 — Save failure had no recovery action

**Before:** IndexedDB write failure left text in memory with only an error status.  
**Fix:** The persistent error state now exposes a keyboard-usable action that selects the draft text for copying.  
**Result:** E2E forces a quota-style IndexedDB failure and verifies the draft remains selectable.

### P2 — Typst split view was too narrow on tablet portrait

**Before:** 768px showed two squeezed columns despite `UI_UX.md` calling for source/preview switching on narrow screens.  
**Fix:** At widths up to 56rem, source and preview are mutually exclusive behind labelled, keyboard-accessible controls; 1024px retains split view.

### P2 — “Waiting to sync” overstated current behavior

**Before:** The new-note row implied an active sync implementation.  
**Fix:** Copy now says the note is saved locally and sync is not set up. The home introduction states the same limit.

### P2 — Papyr had no Czech labels and declared English unconditionally

**Fix:** Added an English/Czech language control, persisted preference, correct document `lang`, and translations for the implemented home, Typst, and whiteboard chrome. The language control is keyboard-first and includes visible text in its accessible name.

The embedded tldraw interface itself remains in its SDK-selected language; this audit did not add a translation download or an unbundled external locale dependency. Papyr's own whiteboard labels are translated.

### P2 — Whiteboard ignored dark mode

**Fix:** Set the tldraw proof editor to follow the system scheme, matching the surrounding page.

### P3 — Control shape and hit areas drifted

**Before:** Buttons used both 0.35rem and 0.4rem radii; navigation links were smaller touch targets.  
**Fix:** Unified control radius/height tokens and raised Papyr links, inputs, and buttons to at least 44px where visible on mobile.

### P3 — Stale phase label and weak hierarchy

**Fix:** Replaced “Phase 0 · local storage proof” with “Local notebook” and removed the eyebrow so the page title leads. Kept the sample draft visually secondary to the local-note workflow.

## Coverage gaps (not implemented)

`UI_UX.md`'s folder tree, breadcrumbs, search, real Markdown editor/preview/export, dialogs, settings, authentication, sync states, and conflict resolver are not present in this repository yet. The home textarea is still a sample local draft; creating a note stores its title and pending operation, not an editable Markdown document. These surfaces were not fabricated as part of a visual pass and need their feature implementation before they can be audited.

Theme follows the operating-system preference; there is no manual light/dark picker. The tldraw SDK controls remain English in a Czech Papyr session because its locale assets are not bundled locally. Physical device, stylus, zoomed-text, and screen-reader checks remain outstanding.
